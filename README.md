**What was optimized:**

Неоптимізований запит: Чотири рази поспіль повністю перераховує, з'єднує та групує один і той самий набір даних у вкладених підзапитах, щоб знайти мінімум і максимум. Це змушує базу робити повний перебір таблиць (Parallel Seq Scan).

**Оптимізований запит:**

Фільтрує та з'єднує таблиці (playlists, music, users) лише один раз у CTE filtered_songs.

Групує та рахує треки лише один раз у CTE cnt_songs.

Використовує віконні функції ROW_NUMBER(), щоб знайти найменшу та найбільшу кількість за один прохід.

Використовує індекси (added_date, song_id, user_id, subscription_type), що замінило повний перебір на швидкий Bitmap Index Scan.

У файлі Explain-Analyze-Query-Plan показано аналіз: виділено місця з Seq Scan та Execution Time: 750.217 ms.

Наступні два файли (Explain Analyze Query Plan With Indexes та Explain Analyze Query Plan With Indexes 2) оптимізовані індексами і показують покращений час виконання запиту (час різний, бо в першому файлі запит з рейтингом з початку 2023 року, де система вирішила, що код буде швидше запускатися і без індексів а лише CTE, а в другому з 2026 року, де використовуються індекси і це виділено у файлі)
